# AGENTS.md — Interview Questions Generator

This file is a guide for human contributors **and** AI agents working in this
repository. It documents the conventions, architecture, and tooling of the
**Interview Questions Generator**, an AI-powered React single-page application.

---

## 1. Project Overview

The Interview Questions Generator lets users enter any job title and receive
three thoughtful, role-specific interview questions generated by Google Gemini
3.5 Flash (served through **Firebase AI Logic / Genkit**).

Key design goals reflected throughout the code:

- **Typed end-to-end.** Every external boundary (user input, AI response, error)
  is validated with **Zod** schemas before it touches application state.
- **Graceful degradation.** Network, rate-limit, and provider errors are mapped
  to user-friendly, typed messages. Transient validation failures auto-retry.
- **Zero boilerplate for the user.** No sign-up, no accounts — enter a job title
  and go.

### Architecture layers

```
[ public/ ]
      │
[ index.html ]  →  [ src/main.tsx ]  →  [ src/App.tsx ]
                                      ↳ [ src/components/* ]        ← presentational
                                      ↳ [ src/hooks/* ]             ← stateful logic
                                      ↳ [ src/lib/* ]               ← pure utilities / AI glue
                                      ↳ [ src/types/inference.ts ]  ← shared schemas & types
```

- **`types/`** is the single source of truth for all schemas and type
  definitions. Both the frontend and the AI-response validation depend on it.
  The same schemas feed into the Gemini `responseSchema`.
- **`lib/firebase.ts`** initializes Firebase and exports the configured Gemini
  model. It imports `systemPrompt` and `geminiJsonSchema`.
- **`lib/inference.ts`** is a thin wrapper that calls `geminiModel.generateContent`
  and returns raw text. All parsing/validation happens in the hook.
- **`hooks/useInference.ts`** orchestrates: loading state, retries, Zod
  validation, error classification, and clearing.
- **`components/`** are purely presentational and receive props — they contain no
  AI or side-effect logic.

## 5. TypeScript Conventions

The project uses an intentionally strict TypeScript configuration:

```json
{
  "strict": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "noFallthroughCasesInSwitch": true
}
```

### What this means for you

- **Always run `npm run type-check`** before pushing. Type errors are bugs.
- **No unused locals or parameters.** If you have a parameter you don't use,
  prefix it with `_` (e.g. `_event`) or omit it.
- **`isolatedModules` is enabled** — don't rely on TypeScript `const enum`
  re-exporting.
- **`moduleResolution: "bundler"`** + `allowImportingTsExtensions` is configured,
  so extensioned imports are fine if you prefer them — but the codebase mixes both.
  Prefer **extensionless imports** for consistency (see §6).
- **`skipLibCheck: true`** is on — don't touch `node_modules` type issues.

}

## 7. React Patterns

### 7.1 Event handlers & callbacks

- Wrap event handlers passed to components in **`useCallback`** with an
  explicit dependency array. Example from `App.tsx`:

```tsx
const handleSubmit = useCallback(async () => {
  const parseResult = jobTitleSchema.safeParse(trimmed);
  if (!parseResult.success) return;
  await submit(parseResult.data);
}, [trimmed, submit]);
```

- State derived from a single source of truth — e.g. `canSubmit` and
  `canClear` in `App.tsx` are computed from `inputValue.length` and
  `isLoading`/`result`.

### 7.2 Hooks

Custom hooks return plain objects and manage their own state:

- `useInference()` → `{ isLoading, result, error, submit, clear }`
- `useCopyToClipboard(resetDelay)` → `{ copied, copy }`

**Do not** call hooks conditionally. The `for` loop in `useInference` calls
`generateInterviewQuestions` inside a `try/catch` — this is the retry mechanism.

### 7.3 Accessibility

- Buttons always have `aria-label` when their text isn't descriptive enough
  (e.g. `"Copy all questions"`, `"Generate interview questions"`).
- Loading sections use `aria-live="polite"`; error sections use
  `aria-live="assertive"`.
- `aria-hidden` is used to hide purely decorative background blobs.
- Form controls use `role="alert"` where appropriate.

## 9. Validation Layer (Zod)

All schemas live in `src/types/inference.ts`. They serve **dual duty**: validating
client input and acting as the contract for the AI response.

### 9.1 User input

```ts
export const jobTitleSchema = z
  .string()
  .min(2, "Please enter at least 2 characters.")
  .max(120, "Job title is too long. Please shorten it.")
  .trim();
```

- Validation is done with `.safeParse()` in `App.tsx` before submission.
- The input field caps at `maxLength={120}` characters.
- Submission requires `inputValue.trim().length >= 2`.

### 9.2 AI response

```ts
export const inferenceResultSchema = z.object({
  description: z.string(),
  question1: z.string().optional(),
  question2: z.string().optional(),
  question3: z.string().optional(),
});
```

- `question1/2/3` are **optional** because the system prompt instructs Gemini to
  omit them (set to nil) when the job title is unrecognized.
- The Gemini response schema (`geminiJsonSchema`) uses Firebase's `Schema`
  object with `optionalProperties` — this is the bridge between Zod semantics and
  the Gemini API's response schema.

### 9.3 Error types

```ts
export type AppErrorType =
  | "network_offline"
  | "rate_limit"
  | "provider_error"
  | "validation_error"
  | "unknown";

export interface AppError {
  type: AppErrorType;
  message: string;
}
```

- `classifyError(error: unknown)` in `src/lib/errorClassifier.ts` maps raw
  errors (Firebase `code`, message strings, `navigator.onLine`) to `AppError`.
- The `useInference` hook uses this: infra errors break the retry loop
  immediately; only `SyntaxError` / `ZodError` trigger a single retry.

## 11. AI Integration Notes

### How the AI pipeline works

1. User submits a validated job title → `useInference.submit(jobTitle)`.
2. `lib/inference.ts` calls `geminiModel.generateContent(jobTitle)`.
3. The Gemini model is configured in `lib/firebase.ts` with:
   - `systemInstruction` → `src/lib/systemPrompt.ts` (a recruiter persona prompt).
   - `responseMimeType: "application/json"` → raw JSON output.
   - `responseSchema: geminiJsonSchema` → structured JSON enforcement.
4. `useInference` parses the raw string, strips any markdown code fences
   (```` ```json ```` → plain JSON), runs `JSON.parse`, then validates with
   `inferenceResultSchema`.
5. On failure, the hook retries **once** (only for validation/parsing errors).
   Infrastructure errors (network, rate limit, provider down) skip retry and are
   classified immediately.

### Toggling the model or prompt

- **Change the model:** set `VITE_MODEL_NAME` in `.env.local` (in
  `lib/firebase.ts`: `model: import.meta.env.VITE_MODEL_NAME ?? "gemini-3.5-flash"`).
- **Change the prompt:** edit `src/lib/systemPrompt.ts` (a plain template
  string exported as default).
- **Change retry count:** edit `MAX_RETRIES` in `src/hooks/useInference.ts`.
- **Change loading animation duration:** edit `DURATION_SECONDS` in
  `src/components/LoadingHighlights.tsx`.

## 13. Testing & Linting

> **Important:** As of this writing, there is **no test framework** (Jest, Vitest,
> etc.) and **no linter** (ESLint/Prettier) configured in this repository.

- **Type safety is the primary guard.** `tsc --noEmit` with `strict`,
  `noUnusedLocals`, and `noUnusedParameters` catches most issues at build time.
- If you are adding a test framework, `vitest` + `@testing-library/react` would
  fit naturally (Vite-native, no extra config). The `useInference` hook and
  `classifyError` function are the highest-value targets for unit tests.
- If you add ESLint, use a config compatible with React 19 + TypeScript 5 +
  Vite. Do not enable rules that conflict with the existing import/export style.

## 14. Making Changes — Checklist

Before opening a PR or committing, ensure:

- [ ] `npm run type-check` passes with zero errors.
- [ ] No unused imports, variables, or parameters (strict TS will flag these).
- [ ] New components follow the `React.FC` + `export default` pattern.
- [ ] Event handlers passed as props are wrapped in `useCallback`.
- [ ] New Zod schemas are added to `src/types/inference.ts` and, if they back a
      Gemini response, also reflected in `geminiJsonSchema`.
- [ ] New error scenarios are mapped in `src/lib/errorClassifier.ts` and covered
      by an `AppErrorType` variant.
- [ ] New Tailwind classes follow the existing dark-theme aesthetic
      (`white/[opacity]` surfaces, indigo accents).
- [ ] All interactive elements have `aria-label` or accessible names.
- [ ] `.env.local` is **not** committed (only `.env.example` should change).
- [ ] If adding dependencies, update `README.md` tech stack table too.
